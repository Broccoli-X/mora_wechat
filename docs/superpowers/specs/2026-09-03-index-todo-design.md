# 首页「今日代办」模块设计

日期：2026-09-03
状态：已实现

## 需求

- 首页新增「今日代办」模块，位于积分模块下方、课表上方。
- 数据源与网页端首页滚动条同源：`/api/progress` `module=todo`，条目在网页端家长维护页（todo-edit.html）增删改，小程序端**只读展示当天清单**。

## 方案取舍

- 不做独立待办管理页：维护入口在网页端家长页，小程序端与积分模块一样只做查看，无勾选完成（网页端 todo 数据本身没有完成状态，服务端 `mastered` 列恒为 0）。
- 新增 `utils/todo.js`：移植网页端 `lib/todo-core.js` 只读所需的最小子集（校验清洗 normalize、短键 payload 解码、occursOn/todosOn「某天有哪些代办」），与 `utils/points.js` 同款只读同步（GET 全量、客户端按 module 过滤、跳过墓碑）。
- 「今日」口径与网页端一致：本地日期 `YYYY-MM-DD`；`daily` 恒真、`once` 比对日期、`weekly` 按本地 `getDay()` 命中勾选（0=周日）。日期解析走本地 `new Date(y,m,d)`，避免 UTC 偏移。

## 数据

- `GET /api/progress?token=` → `{ok, items:[{module:'todo', itemKey, updatedAt, payload}]}`。
- payload 短键 JSON：`{t:内容, m:时间, r:重复(daily|once|weekly), d:日期(仅单次), w:[每周几](仅每周几)}`；内容 ≤60 字，时间 `HH:MM` 必填。
- 空 payload 是删除墓碑，客户端直接跳过（等价删除，与积分同处理）。
- 校验：内容/时间必填，重复类型必须合法；单次必须合法日期，每周几至少一天（0~6 去重升序）。坏 payload 丢弃。

## 页面

- pages/index：积分卡与课表节之间插入「⏰ 今日代办」一节。
- 列表行沿用作业模块的视觉语言：色块 chip（重复类型图标 + 时间，按重复配色：每天绿 #2b8a3e / 单次橙 #e8590c / 每周几蓝 #1d5fbf）+ 内容文本，按时间先后排序。
- 状态文案与作业模块同款：加载「代办同步中…」，空态「今日暂无代办，尽情玩吧 🎉」，失败「代办同步失败 + 重试」。
- onShow / 下拉刷新随其它模块一起加载；无点按跳转（无处可去，纯展示）。
