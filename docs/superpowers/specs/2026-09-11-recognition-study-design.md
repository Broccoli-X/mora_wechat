# 识记学习（综合栏目）设计

日期：2026-09-11
状态：已实现

## 需求

- 网页端新增「识记练习」**内容录入系统**（`recognition-edit.html`）：家长按次（批次）把要给孩子练的内容录进来，按学科分类（识汉字 / 认单词 / 识图），并提供两步拉取接口给外部系统。网页端**不出题、不记成绩**。
- 小程序端在**分类页「综合」栏目**下新增「识记学习」：点开按录入的学科与批次分类浏览 → 查看某批次的卡片 → 点卡片进禅模式；换卡动效参考英语字母卡片。

## 数据来源与协议（两步接口）

与 mora 网页端 `server/README.md`「六、识记练习录入接口」同协议，功能权限键 `recognition`：

- 第一步 `GET /api/recognition/batches?token=[&subject=hanzi|words|image]`
  → `{ok, subject, batches:[{id,subject,title,day,note,count,updatedAt}]}`（`day` 倒序，同日按录入时间倒序）
  → **列表只有概要，没有条目**（网页端同坑：首版按 items 渲染导致全 0 条）
- 第二步 `GET /api/recognition/batch?token=&id=rb…`
  → `{ok, batch:{…概要, items:[{face,answer,extra[,img]}]}}`
- 识图图片本体：`GET /api/image?id=img…`（不带 token，直接当图片地址用）

三科学科口径（与网页端 `lib/recognition-core.js` KINDS 逐字同源）：

| id | 名称 | 学科 | 图标 | 主色 | 条目字段 |
|----|------|------|------|------|----------|
| hanzi | 识汉字 | 语文 | 📖 | #c9392b | face 单字 / answer 拼音 / extra 组词 |
| words | 认单词 | 英语 | 🔤 | #177a3e | face 单词**或整句**（大小写照原样）/ answer 中文 / extra 音标 |
| image | 识图 | 其他 | 🖼️ | #8a5a2b | face emoji 或 img / answer 名称 / extra 英文 |

### 客户端不做字面校验（2026-09-11 事故后的决定）

网页端在上线当天又提交了 `1efd1b2 认单词支持整句：按行录入、保留大写（不再强制小写）`：
face 从「小写单词 ≤32 字」放宽为「单词或整句 ≤60 字、保留原样大小写」，answer 上限 20→30。
小程序端当时复刻了旧规则（小写单词正则 + 转小写），结果**静默丢掉含空格的条目**——
真机「Unit 1 I'm Liu Tao」11 条只显示 6 条（`Yang Ling` / `Wang Bing` / `Liu Tao` / `Su Hai` / `I am` 全被吃掉，
其余 6 条还被转成了小写）。

**决定**：客户端只做「能不能渲染」与长度保护（`FACE_MAX` 60 / `ANSWER_MAX` 30 / `EXTRA_MAX` 40 截断），
**不再复刻服务端的字面校验**——内容以服务端为真源（写入时网页端与服务端已按同口径校验），
客户端再判一次只会在规则漂移时悄悄吃内容。只有「没字/没图可认」的空条目与未知学科才丢。
认单词的整句按长度分档字号（`fs`：≤10 字 `lg` / ≤24 字 `md` / 其余 `sm`，网格最多 3 行、
禅模式最多 4 行），避免长句撑破卡面。

同时**把旧版整批缓存作废**：缓存键 `mora-recognition-batch-v1` → `v2`，读到 v1 立即清除。
原因：v1 里存的是修复前写下的内容（face 被转成小写、含空格的条目已丢），
不清掉的话修复后进页面仍会先渲染出一版「小写 + 缺条」的卡面（离线时更是长期如此）。
清掉后一律以服务端为准，原样大小写。

## 方案取舍

- **只读浏览，不做 ⭐ 掌握标记**：网页端口径「本站不出题、不记成绩」，服务端 `MODULES` 白名单已把 `recognition` 摘掉（`/api/progress` 不收该 module）。故本期不引入掌握进度与同步，禅模式改为显示**当前序号「3 / 12」**。后续若家长需要，需先在网页端把 recognition 加回 MODULES。
- **缓存为第一读取点**：本地缓存列表与按 id 的整批内容（`mora-recognition-*`），离线/首屏直接用缓存渲染，再静默拉服务端刷新；批次内容按 `updatedAt` 覆盖。契合服务端「内容型数据以服务端为真源」。
- **禅模式取数交接**：批次页点卡片时把整批内容交给 zen（内存，免一次请求），深链/重启回落到本机缓存。交接**记下所属家庭**：换家庭登录时本机缓存会被 `purgeLocalFamilyData` 清掉，内存交接若不带家庭判定会串上一家的内容（与本地缓存同一条隔离红线）。
- **列表不预取条目**：沿用网页端策略（概要列表 + 按 id 取整批），避免开页 N 个请求；批次卡只显示名称/学科/日期/条数/备注。
- **三页结构**：列表（学科分节）→ 批次（卡片网格）→ 禅模式。层级与古诗/字母卡一致。
- **禅模式左右滑动 = 顺序上一张/下一张（首尾循环）**：批次是家长排好序的一组内容，顺序比随机更适合认读；字母卡是 26 个字母的随机抽认，语义不同，但**动效完全同款**（方向感知出/入 + 奇偶异名强制重放 + 轻震动）。
- 不做：出题、计分、录音跟读（网页端也不出题；发音类需求另议）。

## 页面

### 列表页 pages/recognition/recognition

- 顶部标题 + 概览胶囊「共 N 批 · M 条」。
- 按学科**分节**（识汉字 → 认单词 → 识图，空科不呈现）：节头为学科色块 + 名称 + 批次数。
- 批次卡：批次名、学科名 · 日期（M月D日 星期X）· N 条、备注（有才显示）。
- 点批次卡 → 批次详情页。空态引导家长去网页端录入。
- 权限：`ensurePerm('recognition')` 未开通整页不呈现（与字母卡/古诗页同款）。

### 批次页 pages/recognition/batch?id=rb…

- 头部：批次名 + 学科胶囊 + 日期/星期 + 「N 条」+ 备注。
- 「🔀 开始认读」按钮 → 禅模式第 1 张。
- 卡片网格（按学科列数：识汉字 3 列大字 / 认单词 2 列 / 识图 2 列）：主面 + 答案行 + 附注行。
- 点卡片 → 禅模式该张。识图 image 加载失败就地回退 emoji/🖼️，不白屏。
- 404（批次已被家长删除）提示后返回；离线走缓存。

### 禅模式 pages/recognition/zen?id=&i=

- 自绘导航（`navigationStyle: custom`）：✕ 固定左上角（右上角是小程序胶囊，不能放），顶部胶囊显示「批次名 · 3 / 12」。
- 大卡：与列表卡同款内容放大（识图显示大图）。
- 左右滑动换卡：左滑下一张、右滑上一张，首尾循环；方向感知——旧卡飞向滑动侧、新卡自反侧滑入，`in/out × l/r × 奇偶` 12 个类名各绑不同 `animation-name`（CSS 同名动画不重放），换卡交替换名强制重放；轻震动。
- 权限：`ensurePerm('recognition')` 深链误入也挡住（提示后退回）。

## 入口

- `app.json` 注册三页；`sitemap.json` 无需改动（默认 allow）。
- 分类页「综合」组新增学科节「识记」（🧠，`#7c3aed`），条目「识记学习」，`perm='recognition'`：未开通家庭入口不呈现，深链由页面登录门 + 整页拦截接管。
